# Memory Bank: Product Context

## Проблема

Нужен практический репозиторий, где критерии PWA, Manifest, Service Worker, кэш, офлайн и установка закрепляются на живом React-коде, а не только в теории.

## Решение

Приложение с навигацией по учебным модулям (Manifest, SW, Offline, Install, …). Каждый модуль — живой пример + краткие пояснения в UI. Lighthouse PWA audit проходит на production-сборке.

## Целевые возможности

1. Корректный Web App Manifest (имя, иконки, `display`, цвета)
2. Зарегистрированный Service Worker с контролируемым обновлением
3. Precache статики и разумный runtime-кэш
4. Офлайн-fallback (страница или режим «вы offline»)
5. Install prompt / подсказка установки (где поддерживает браузер)
6. (Опционально, поздние этапы) Push, Background Sync, Share Target

## Приоритеты

| Приоритет | Описание                                          |
| --------- | ------------------------------------------------- |
| P0        | Manifest + базовая installability                 |
| P1        | Service Worker: регистрация, precache, обновление |
| P2        | Офлайн UX, runtime caching, учебные экраны        |
| P3        | Продвинутые API браузера (по желанию)             |

## MVP (краткосрочные цели)

- [ ] Базовое React-приложение с навигацией по учебным разделам
- [ ] Web App Manifest и набор иконок
- [ ] Service Worker (ручной или через vite-plugin-pwa)
- [ ] Офлайн-доступ к оболочке / fallback
- [ ] Проверка: Lighthouse PWA + установка на устройство

Чекбоксы MVP синхронизируются при `/close-task` (см. `docs/project/product-roadmap.md`).

## UX-ожидания

- Понятные учебные экраны на русском
- Явные индикаторы offline / update / install
- Mobile-first: удобно на телефоне (установка PWA), нормально на планшете и десктопе

- Разработка по TDD; Vitest + Playwright до продуктовых фич (фаза 0 плана)
