# Технологии: Frontend

## Область применения

Правила для изменений во frontend-коде (`src/`): выбор библиотек, работа с UI, состоянием, рендером и стилями.

## Ключевые правила

- Перед любыми решениями по зависимостям и инструментам проверять `package.json`.
- Для локального состояния компонента использовать `useState` по умолчанию.
- Для нелокального состояния (несколько экранов/модулей) — React Context или выделенный store; **не добавлять** state-менеджер без явной необходимости и согласования.
- Стили: только SCSS (отдельные `.scss` рядом с компонентом); через `sass-embedded`.
- Правила раздела «Антипаттерны и ограничения производительности» обязательны при написании и рефакторинге кода.

## Стек

- **React**, **React DOM** — UI
- **TypeScript** — типизация
- **Vite** — сборщик, dev-сервер
- **@vitejs/plugin-react** — плагин Vite для React
- **SCSS** — оформление (`sass-embedded` в devDependencies); файлы `.css` не использовать

## UI-компоненты

- На текущем этапе — **самописные React-компоненты** без обязательной UI-библиотеки.
- При добавлении headless-примитивов (диалоги, табы и т.п.) предпочитать библиотеки **без навязанной дизайн-системы** и с поддержкой TypeScript.
- Целевая платформа — **браузер** (телефон, планшет, десктоп); mobile-first, на широких экранах — полноценный адаптив (не «растянутая мобильная» вёрстка).

## Линтинг и форматирование

- **ESLint** — линтер (typescript-eslint, eslint-plugin-react-hooks, eslint-plugin-react-refresh, globals)
- **Prettier** — форматирование (prettier-plugin-css-order, prettier-plugin-organize-attributes, prettier-plugin-organize-imports)
- **Husky + lint-staged** — pre-commit форматирование staged-файлов

## Антипаттерны и ограничения производительности

### Подсчёт количества элементов

- **Запрещено:** использовать паттерн `filter(...).length` для подсчёта элементов, соответствующих условию.
- **Обязательно:** использовать `reduce` для вычисления числового агрегата (`count`, `sum` и т.п.), чтобы избежать создания промежуточного массива.

**Плохо:**

```ts
const unreadCount = notifications.filter((n) => !n.readAt).length;
```

**Хорошо:**

```ts
const unreadCount = notifications.reduce((count, n) => (n.readAt ? count : count + 1), 0);
```

### Обновление состояния без фактических изменений

- **Запрещено:** возвращать новый массив/объект из `setState`, если содержимое по факту не изменилось.
- **Обязательно:** возвращать `prev`, когда новое состояние эквивалентно предыдущему.

### Лишние аллокации в рендере

- **Избегать:** создания промежуточных массивов/объектов в рендере без необходимости.
- **Предпочитать:** `useMemo` для повторно используемых вычислений.
- **Для нового набора данных:** использовать `filter`/`map`/`slice` (и при необходимости `useMemo`), а не `reduce` с накоплением массива через `...acc`.

## Чеклист для ИИ

- [ ] `package.json` проверен перед выбором библиотек/инструментов.
- [ ] Для state выбран корректный подход (`useState` для локального; Context/store — только при реальной необходимости шаринга).
- [ ] Для подсчётов использован `reduce`; для новых наборов данных применены `filter`/`map`/`slice` и `useMemo` при необходимости.
- [ ] Избежаны лишние аллокации в рендере и лишние обновления состояния.
