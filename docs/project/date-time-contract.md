# Контракт даты и времени

> **Назначение:** правила для TypeScript и UI в клиентском приложении.

## 1. Цель

- **Момент времени** в коде — тип **`Date`** (или библиотека по явному решению в `package.json`).
- **Сериализация** (JSON, `localStorage`) — **ISO 8601 / RFC 3339** в UTC, строка вида `2026-07-23T10:15:00.000Z`.
- **Отображение пользователю** — локаль браузера через `Intl.DateTimeFormat` или явное форматирование; не смешивать «сырой» ISO в UI без пояснения.

## 2. TypeScript / React

- Хранить момент как `Date`; при чтении из JSON — `new Date(isoString)`.
- Для **только даты** (без времени) — строка `YYYY-MM-DD` или `Date` с осторожностью по timezone; документировать выбор в задаче.
- **Timestamps в ms** (`Date.now()`) — только для измерения длительности или sortable id, не как основной календарный контракт в UI.

## 3. Service Worker и кэш

- Версионирование кэша SW — строки/хеши сборки, не календарные даты, если только не учебный пример.
- Заголовки HTTP `Date` — не парсить вручную без необходимости.

## 4. Чеклист для ИИ

- [ ] Моменты времени — `Date` или согласованный тип из зависимостей
- [ ] В JSON/`localStorage` — ISO UTC строки
- [ ] В UI — локализованное форматирование
